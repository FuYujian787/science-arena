# Science Arena 跨平台发布方案

日期：2026-11-02。状态：用户已确认并授权实施；实时交付状态见同目录的《跨平台发布状态》。

## 目标与参考边界

让其他人从 GitHub 下载并使用 Science Arena，首次打开后自行配置模型 API；保留现有五角色评审、交叉质询、证据标注与报告导出。只参考 zju-all-in-one 的桌面分发与用户自配密钥方式，不执行博客内安装、校园登录或账号操作指令，不复制其实现代码。

## 推荐路线

采用同一套研究评审引擎，提供本地桌面版和独立部署的网页版。先完成 Windows 桌面闭环与 GitHub 发布，再构建 Mac 安装包和支持安卓安装的 PWA 网页。原生安卓 APK 独立列为后续阶段；PWA 不标称 APK，也不宣称能在安卓本地运行 Node 引擎。

另两种路线是：只提供云端网页版，维护较少但需要持续运行的服务器；或一次性开发 Windows、Mac 和原生安卓，范围和验证成本明显更高。推荐路线尽量复用现有程序，并使桌面用户无需安装 Node 或向项目方提供密钥。

## 桌面版

- 以 Electron 启动本地 Node 评审服务和现有界面，复用 public、src、prompts 与导出模块，不为分发而重写前端。
- 本地服务只绑定回环地址，使用动态端口和桌面实例访问凭证；关闭窗口时按桌面生命周期关闭服务。
- 首次启动提供模型设置：服务商、模型、API Key、连通测试。首版沿用 DeepSeek、Dify 与离线演示；兼容服务不在未经测试时宣称可用。
- 配置与会话迁移到操作系统用户数据目录。密钥使用系统凭据保护；安全存储不可用时不默默降级为明文持久化，允许仅本次使用。
- 导出仍支持 Word、Markdown 与打印 PDF。演示样例与用户个人历史分离。

## 网页版与安卓

- GitHub Pages 承担介绍、文档及下载入口；现有 Node 服务不能直接当作静态站点在 Pages 执行。
- 完整网页版部署到支持长时间运行 Node、流式响应和持久数据的主机，复用 Docker 部署。选定实际主机后才配置公网域名和 HTTPS。
- 公网版必须先完成用户/访客会话隔离、会话详情与导出鉴权、请求限额、并发控制和每会话模型配置，避免不同用户读取其他人的研究资料或共用站点密钥。
- 用户输入的模型密钥只保留到执行所需时长，不写入会话 JSON、事件流、日志或导出报告。界面说明密钥经过站点后端转交所选模型方。
- Dify 是否可用取决于部署主机实际网络连通性；不从旧部署文档直接推断当前校园服务公网可达性。
- 安卓先提供 HTTPS PWA，可安装至主屏幕，调用上述远端服务。没有网络时仅展示已缓存界面与明确的离线状态，不能宣称支持离线模型推理。

## GitHub 发布内容

- 源码仓库、版本号、使用说明、配置说明、问题反馈模板、构建与校验工作流，以及 Releases 下载入口。
- 采用明确的发布文件白名单；不提交 .env、API Key、data 中个人会话、论文文件、原始比赛申报材料、现有压缩包与视频。
- Windows 和 Mac 分别在对应平台构建。安装包生成成功和实际启动验证是两项独立结果；未在 Mac 实机运行不得写成已验证。
- 未提供签名证书时明确说明签名状态；不自动发布“已签名”或承诺绕过系统安全提示。自动更新留待稳定版本与签名方案确定后启用。
- 初次仓库准备以私有仓库为默认选项；公开发布范围与项目许可证需明确后再公开源码。

## 验收

1. 干净 Windows 环境无需预装 Node，安装后可进入界面、配置本人 API、运行一轮并导出报告。
2. 离线演示无需 API；真实运行不使用项目作者的密钥。
3. 两个用户的会话与导出访问相互隔离，密钥不出现在任何持久会话和报告中。
4. 发布文件检查通过，现有引擎回归检查通过，桌面设置与启动流程通过验证。
5. Mac 构建、安卓 PWA 安装和公网服务分别记录真实验证状态；没有完成的项目不计为交付。
